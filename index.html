The Interference Budget

A fixed-size memory can read an endless stream of facts without ever growing. That is not magic and it is not free. Every fact you write in spends from the same budget, and this page lets you watch the bill arrive.

A fixed-size fast-weight memory S = Σ kᵢvᵢᵀ stores a stream of key→value bindings without ever growing, but because every binding is added into the same matrix, reading back an earlier value returns the true value plus a cross-talk term Σⱼ≠ᵢ (kᵢ·kⱼ) vⱼ whose size is set by how much the keys overlap — so recall error grows like √(N/d) and is near-zero only when the keys are near-orthogonal.

That sentence is falsifiable. If you can make recall stay perfect while packing in many correlated keys, the claim is wrong. Every control below exists so you can try.

Before you touch anything

Audience. You have seen attention (softmax(QKᵀ)V), you can read a matrix–vector product, and you have trained something small in PyTorch or NumPy. You do not need to know linear attention, fast weights, Hopfield networks, or BDH — that is what this builds.

Prerequisites. Dot products, outer products, vector norms, the idea that softmax attention keeps one key–value pair per past token in a cache that grows with sequence length.

By the end you will be able to:

  1. Write the fast-weight update and read as two one-line equations and say what each symbol is.
  2. Predict, before running it, whether a given (N, d, key-correlation) setting will recall cleanly.
  3. Derive the cross-talk term and explain why it is exactly zero for orthogonal keys.
  4. Show that this memory is linear attention with a running state, not an approximation bolted on.
  5. Point to where this mechanism sits inside Dragon Hatchling (BDH) and BDH-CQ, and name what BDH adds on top.
  6. State the most important limitation: a fixed state forgets through interference, and within-session memory is not durable learning.

Estimated time: 12–15 minutes to read and play; the 60-second test is at the end.

1 · The write: memory as a running sum of outer products

Softmax attention remembers the past by keeping it: every token leaves a (key, value) pair in a cache, and answering a query means scanning all of them. The cache grows with sequence length, so memory and compute per token grow too.[7]

A fast-weight memory does the opposite. It never stores individual pairs. It keeps one matrix S and, for each new binding (kᵢ, vᵢ), adds the outer product kᵢ vᵢᵀ into it:

write    Si = Si-1 + ki viT      (S is d×m, fixed size, independent of i)

This is a Hebbian rule: the pattern kᵢ and the pattern vᵢ that are active together get their connection strengthened. Schmidhuber proposed exactly this "fast weight" scheme in 1992 [1]; Ba et al. revived it in 2016 [2]. Below, step through 20 writes and watch the matrix fill in. Nothing is being learned — the keys and values are fixed random vectors, and each frame is one honest outer-product addition.

Key idea to carry forward: after 20 writes the matrix looks like noise, but every binding is still in there — folded, not filed. Section 2 pulls one back out.

2 · The read: what you get back is signal + cross-talk

To recall the value for a key q, multiply:

read    out = ST q = Σj (kj · q) vj

Now set q = kᵢ, one of the keys you stored, and split the sum into the term you want and everything else. With unit-norm keys kᵢ·kᵢ = 1, so:

out = vi + Σj≠i (ki · kj) vj     = signal + cross-talk

The cross-talk is not noise the model added. It is the other stored values, leaking in through the dot products between their keys and yours. If every other key is exactly perpendicular to kᵢ, every kᵢ·kⱼ = 0 and recall is exact. As keys tilt toward each other, their values bleed into your answer.

Room to spread out. Random vectors in high d are nearly perpendicular.

Try to break the claim. Push N to 60 with d = 4: recall collapses. Now push d to 128: it snaps back, because 60 random vectors in 128-space are still almost perpendicular. Now hold d = 128 and raise ρ: the collapse returns even though there is "room," because you removed the perpendicularity by hand. The memory's capacity was never about size in bytes — it is about geometry.

Misconception check

"A bigger state means a longer memory." Not quite. A d×m state has a fixed number of independent directions (min(d, m)). Beyond that, new writes must reuse directions already spoken for, and interference is forced by linear algebra, not by a design choice you can tune away.

3 · The law: recall error grows like √(N/d)

The cross-talk term is a sum of N−1 roughly independent random vectors, each scaled by a dot product kᵢ·kⱼ. For random unit keys in d dimensions, E[(kᵢ·kⱼ)²] ≈ 1/d. Values have unit norm. So the expected squared error is about (N−1)/d, and:

RMS recall error ≈ √( (N−1) · ( ρ² + (1−ρ²)/d ) )   →   ≈ √(N/d)  when ρ = 0

This is the same capacity story told by associative-memory theory: classic Hopfield networks store ≈ 0.14 d patterns before recall breaks [3]; modern Hopfield / attention pushes that much higher by making the read nonlinear [4]. Our linear memory sits at the conservative end — and you can measure it.

4 · Forgetting: interference vs decay

There are two different ways a fixed state loses information, and conflating them is a common error.

MechanismEquationWhat it doesWhat it costs
Interference (Section 2–3) Sᵢ = Sᵢ₋₁ + kᵢvᵢᵀ All bindings kept with equal weight; they blur together as they pile up. Old facts never removed, just buried. Error grows with N.
Decay (forget gate) Sᵢ = λ·Sᵢ₋₁ + kᵢvᵢᵀ, λ<1 Down-weights the past every step; recent bindings dominate. Distant facts are genuinely gone, whether or not they still matter.

Gated linear attention, RetNet, Mamba's state updates, and DeltaNet all live in this table — they differ mainly in how λ and the write are computed (scalar, diagonal, data-dependent, or a rank-1 correction) [5][6].

1.000 = pure interference. Lower = aggressive recency.
recall error vs binding age (0 = most recent)

Read the shape. At λ=1 the error curve is roughly flat — every binding is equally degraded. Drop λ and the curve tilts: recent bindings get sharp, old ones fall off a cliff. Neither is "better." A model that must answer questions about the start of a long document wants λ near 1 and pays in interference; a model tracking a fast-changing state wants low λ and pays in amnesia.

Misconception check

"A recurrent state that never grows can therefore remember arbitrarily long histories." It can process an unbounded stream with bounded memory — but it cannot retain unbounded content. The claim on this page is the honest version of that sentence.

5 · This is not like linear attention. It is linear attention.

Take softmax attention and replace exp(qᵀk) with a plain feature-map dot product φ(q)ᵀφ(k) [8]:

softmax:  outᵢ = Σⱼ ( exp(qᵢ·kⱼ) / Zᵢ ) vⱼ   — needs all (kⱼ,vⱼ), cache grows
linear:   outᵢ = Σⱼ≤ᵢ ( φ(qᵢ)·φ(kⱼ) ) vⱼ = φ(qᵢ)ᵀ ( Σⱼ≤ᵢ φ(kⱼ) vⱼᵀ ) = φ(qᵢ)ᵀ Sᵢ

The parenthesised term Sᵢ = Σⱼ≤ᵢ φ(kⱼ)vⱼᵀ is our memory, and it obeys Sᵢ = Sᵢ₋₁ + φ(kᵢ)vᵢᵀ — the exact Hebbian write from Section 1. So "linear attention," "a fast-weight matrix," and "a Hebbian associative memory" are three names for one object. The move from softmax to linear is precisely the move from a cache you scan to a state you accumulate: constant memory, linear-time, and the interference budget you have been spending all page.

Softmax can concentrate almost all weight on the true match; the linear read spreads a tail across the rest — that tail is the cross-talk.

Switching φ to relu makes the contributions non-negative and sparse — most bindings contribute exactly zero. Hold that thought for the next section: it is the doorway into BDH.

6 · Where this mechanism lives: Dragon Hatchling (BDH) & BDH-CQ

Pathway's Dragon Hatchling (BDH) is a Post-Transformer architecture whose stated design move is to reformulate attention as synaptic memory that updates as the model reads [9]. The concept you just explored is not analogous to BDH's mechanism — the fast-weight / linear-attention state is the mechanism, in its GPU-friendly form. This module says precisely what BDH keeps, what it adds, and how strong the evidence is for each part.

The shared skeleton

This page's toy
keys/values: fixed random vectors
write:  S ← S + kᵢ vᵢᵀ

S is a hand-built associative memory
BDH-GPU, as described in the paper developer-reported
keys/values: ReLU, low-rank projections of the
  neuron activations x (non-negative, ~5% active)
write:  synaptic state σ ← σ + (linear-attention outer product)
read:   contextual term = σ applied to current activations
σ is a trained model's synapse-level working memory

BDH's own framing: neurons and synapses following local rules, where "attention becomes synaptic memory through Hebbian writes" [9][10]. The outer-product write in Section 1 is that Hebbian rule. BDH-GPU makes it trainable and scalable by (1) generating the keys/values from ReLU-low-rank transformations of a sparse non-negative activation vector, and (2) sharing parameters so the same synaptic fabric carries memory, adaptation, and reasoning [9].

BDH-CQ: the additive-per-demonstration special case

BDH-CQ is a later system in the family that "learns from demonstrations and reasons without a written chain of thought" [11]. Its technical report relates its contextual memory to attention, fast-weight memory, and linear-attention views of contextual association — and calls out a special case where the state accumulates additively, one contribution per demonstration [11]. That special case is exactly S = Σ kᵢvᵢᵀ from Section 1, with the index i running over demonstrations instead of tokens.

Two consequences you can now reason about directly:

  • Adaptation without weight updates. BDH-CQ reports solving unseen ARC-AGI-style tasks with no evaluation-task demonstrations in training and no parameter updates at inference [11]. In our terms: the "learning" is the accumulation of outer products into S during the forward pass. The weights are frozen; the state carries the new rule. Contrast HRM / TRM, which take a backward pass per task [12].
  • Demonstration coverage is an interference-budget question. More demonstrations of a task sharpen the recalled rule — up to the point where their key overlap starts blurring it, the same trade-off you watched in Section 3. BDH-CQ's low / medium / high "effort" settings spend more recurrent compute reading that state, not more chain-of-thought tokens [11].
Evidence discipline

Everything labelled developer-reported comes from Pathway's own paper or technical report, not from an independent reproduction. A benchmark score is not a deployment; a reported number is not an external replication. The toy on this page is an illustration — a hand-built memory, not a BDH checkpoint, and it must not be cited as BDH behaviour. What is solid: the linear-attention / fast-weight equations (Sections 1–5) are standard, published, and cited below.

Where BDH-CQ has no direct role

The √(N/d) capacity law and the softmax-vs-linear comparison are properties of linear attention in general. BDH-CQ neither introduced nor depends on them; it inherits them by building on the linear-attention family. Saying otherwise would be inventing a connection.

7 · Limitations, failure cases, and honest labels

  1. The toy uses near-ideal keys. We hand it random or deliberately correlated unit vectors. A real model must learn to place near-orthogonal keys, and often does not — so real linear-attention models forget more than the √ law's best case.
  2. Linear attention is strictly less expressive than softmax + full cache for exact retrieval. A growing KV cache can return any past value exactly; a fixed state cannot, once you exceed its rank. Benchmarks that reward precise long-range copying expose this [6].
  3. Within-session memory is not learning. Everything here happens in S during one forward pass. Close the session and it is gone. This is the stability–plasticity line: durable capability lives in weights, and consolidating useful fast state into slow weights is an open problem BDH's authors name explicitly [9].
  4. The √ law is an average. It assumes random keys and unit values. Structured or adversarial keys, or heavy-tailed value norms, break it in both directions.
  5. Illustration vs computation. Sections 1–5 are live arithmetic in your browser. Section 6's BDH equations are transcribed from the papers and simplified; the neuron–synapse diagram is a teaching schematic, not a trace of a real BDH run.

Then check against the number the sandbox prints. If your prediction was in the right ballpark and you can say why in one sentence — "error scales with √(N/d) because cross-talk is a sum of N−1 independent leaks each of typical size 1/√d" — the claim at the top of the page is now yours.
